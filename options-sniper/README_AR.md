# نظام قنص العقود (Options Sniper) — دليل التشغيل

## الملفات
| الملف | وظيفته |
|---|---|
| `CLAUDE.md` | تعليمات كلود كود (القوالب والقواعد) — يُقرأ تلقائياً |
| `config.py` | كل الإعدادات (الأوزان، العتبة 85، السقف 5، الميزانيات) |
| `uw.py` | عميل Unusual Whales — كل الطلبات والمسارات في مكان واحد |
| `finviz.py` | Finviz Elite — اكتشاف مرشحين فقط، لا يعطي نقاطاً |
| `technical.py` | تحليل فريم 15د: الكسر، ATR، الفوليوم، الهدف، الوقف |
| `scoring.py` | حساب النقاط وفلتر الميزانية (السعر × 100) — كله كود، مو كلود |
| `compose.py` | صياغة الرسالة العربية (كلود + بديل بايثون احتياطي) |
| `state.py` | عدّاد التنبيهات اليومي محمي بقفل ملف |
| `journal.py` | كتابة `journal.csv` لمعايرة العتبة بعد التجربة الورقية |
| `scanner.py` | الفحص الشامل كل 30 دقيقة |
| `monitor.py` | مراقبة فريم 15د + تنبيهات الخروج كل 5 دقائق |
| `telegram_send.py` | الإرسال لتيليجرام |
| `positions.json` | تكتب فيه صفقاتك المفتوحة عشان يراقبها للخروج |

## خطوات التشغيل

**1. جهّز المفاتيح**
```bash
cp .env.example .env      # ثم عبّي القيم بالمحرر
```
- `UW_API_KEY` من حسابك في Unusual Whales
- بوت تيليجرام من @BotFather، ثم أرسل رسالة للبوت وافتح
  `https://api.telegram.org/bot<TOKEN>/getUpdates` لأخذ `chat_id`
- `FINVIZ_AUTH` اختياري تماماً — النظام لا يستخدمه في احتساب النقاط

**2. ثبّت المتطلبات واختبر تيليجرام**
```bash
pip install -r requirements.txt --break-system-packages
python3 telegram_send.py          # لازم توصلك رسالة "اختبار" بتيليجرام
```

**3. تشغيلة تجريبية بدون إرسال**
```bash
python3 scanner.py --dry-run --limit 5
```
`--dry-run` يطبع الرسالة في الطرفية بدل تيليجرام، ويتجاهل سقف الـ 5 اليومي.
راجع الرسالة قبل ما تعتمد عليها.

**4. الاختبارات**
```bash
python3 -m pytest tests -q        # 24 اختبار
```
شغّلها بعد أي تعديل على `config.py` — تحمي قواعدك الأربع الحرجة.

**5. الجدولة**
```bash
crontab crontab.txt               # عدّل SNIPER= لمسارك أولاً
```
راجع `crontab.txt` — فيه نسخة صيفية وأخرى شتوية.

**6. بعد ما تدخل صفقة**
انسخ `positions.example.json` إلى `positions.json` وعدّله:
```json
[{"ticker":"UBER","contract":"UBER 260911 C76","entry_price":0.85,
  "option_symbol":"UBER260911C00076000"}]
```
`option_symbol` بصيغة OCC — نفس الصيغة اللي تجيك في التنبيه.

## قواعد ثابتة (مبنية داخل الكود)
- سقف 5 تنبيهات دخول باليوم — الأعلى نقاطاً أولاً، محمي بقفل ملف
- **تنبيهات الخروج لا تُحتسب ضمن السقف** — ما ينفع تُمنع من إغلاق صفقة قائمة بسبب حصة
- العتبة 85 من 100 (عدّلها في `config.py` بعد التجربة الورقية)
- فلتر الميزانية: تكلفة العقد = السعر (ask) × 100 ≤ الفئة
- كل فئة تأخذ عقداً مختلفاً — لا تكرار
- جني ربح عند +60% / وقف خسارة عند −40%

## فلاتر تمنع صفقات سيئة
- **الدخول المتأخر**: لو الكسر وصل هدفه أصلاً (أقل من 0.75 ATR متبقٍ) → لا تنبيه.
  الدخول المتأخر أغلى من الإنذار الكاذب.
- **الكتالايزر المعاكس**: خبر تخفيض تصنيف على إشارة كول = 0 نقاط، لا 20.
- **السيولة**: السبريد ≤ 8% أو ≤ 6 سنتات (أيهما أرحم) + فتوح ≥ 300 عقد.
- **بيانات ناقصة** → `NO_TRADE`، لا تخمين.

## معايرة العتبة بعد أسبوعين
`journal.csv` يسجّل كل تنبيه بتفصيل النقاط الأربع لكل عقد.
بعد ~20 تنبيهاً عبّي عمودَي `outcome` و `result_pct` يدوياً، ثم:
- إن كانت أغلب الخاسرات نقاطها 85–88 → ارفع `THRESHOLD` إلى 88
- إن كانت `technical` عالية في الرابحات و `flow` عشوائية → عدّل `WEIGHTS`
- إن كانت أغلب الخسائر من فئة 🔴 → قلّل الميزانية أو احذف الفئة

## ⚠️ قبل أي فلوس حقيقية
أسبوعان إلى شهر تجربة ورقية. النسب المعروضة **تقديرات بالدلتا**، وتتجاهل
الغاما والثيتا — الفرق يكبر كلما اقترب الانتهاء. النظام يعطي إشارات
احتمالية، ونسبة الإنذارات الكاذبة عالية بطبيعتها.

## ملاحظة على مسارات UW
كل المسارات وأسماء الحقول في `uw.py` مأخوذة من مواصفة OpenAPI الرسمية
(`https://api.unusualwhales.com/api/openapi`)، وليست تقديرية.
أهم تصحيح: `option-chains` يرجّع **مصفوفة نصوص** بدون `greeks=true` —
لذلك يُطلب دائماً بـ `greeks=true`، مع بديل `/option-contracts` عند اللزوم.

# النشر على Railway

`scheduler.py` عملية واحدة تبقى شغّالة وتطلق المهام في وقتها بالضبط.

## الخطوات

**1. اربط المستودع**
`https://railway.com/new` → **Deploy from GitHub repo** → `salem0557/cloud`

**2. اضبط جذر الخدمة**
`Settings → Source → Root Directory` → **`/options-sniper`**

⚠️ انتبه: `/options_scanner` (شرطة سفلية) مشروع قديم مختلف. الصحيح
`/options-sniper` بشرطة عادية.

**3. احذف أي خدمة أخرى**
جذر المستودع فيه `Procfile` قديم (`worker: python bot.py`) قد يجعل Railway
ينشئ خدمة ثانية اسمها `worker`. **كل خدمة تُحاسب لحالها** — احذفها:
`الخدمة → Settings → Delete Service`.

المطلوب: **خدمة واحدة فقط**.

**4. أضف المتغيرات**
`Variables → New Variable` — خمسة:

| Variable | Value |
|---|---|
| `UW_API_KEY` | مفتاح Unusual Whales |
| `TELEGRAM_BOT_TOKEN` | توكن البوت |
| `TELEGRAM_CHAT_ID` | رقم الشات |
| `USE_CLAUDE_COMPOSER` | `0` |
| `SNIPER_DATA_DIR` | `/data` |
| `FINVIZ_AUTH` | توكن Finviz Elite |

`USE_CLAUDE_COMPOSER=0` ضروري: الحاوية ما فيها `claude` CLI، فتُصاغ الرسالة
ببايثون — نفس القالب ونفس الأرقام.

**5. أضف القرص الدائم** ← لا تتخطَّ هذه
`Settings → Volumes → Add Volume` → Mount path: `/data` → **1 GB**

قرص الحاوية مؤقت. بدون القرص الدائم، كل إعادة نشر تمسح عدّاد التنبيهات
و `journal.csv` كاملاً — أي تفقد بيانات معايرة العتبة.

**6. تحقق**
`Deployments → View Logs`، لازم تشوف:
```
scheduler up — scan every 30m, monitor every 5m, data in /data
market closed — weekend (Sat 08:04 ET)
```
لو ظهر `data in /app` بدل `/data`، فمتغير `SNIPER_DATA_DIR` ما انضبط.

# دور Finviz Elite

## ما لا يفعله
**لا يعطي نقاطاً إطلاقاً.**

Finviz يقول لك إن سهماً عليه فوليوم نسبي عالٍ اليوم. لا يقول لك هل كسر
مستوى على فريم 15 دقيقة — وهذا بالضبط ما تقيسه الـ30 نقطة التقنية.

النسخة الأولى من `scanner.py` كانت تمنح 19 من 30 لمجرد ظهور الرمز في
قائمة Finviz، بأرقام مزروعة يدوياً (`break_distance_atr = 0.5`،
`volume_ratio = 2.0`). سهم لم يتحرك كان يعبر القائمة المختصرة. هذا محذوف.

## ما يفعله
**يوسّع الشبكة.**

`uw.flow_alerts()` يرجّع أحدث 200 تنبيه في السوق كله. سهم عليه تدفق حقيقي
قد **يفوت هذه النافذة** لمجرد أن غيره كان أحدث منه.

فالمسار صار:

```
1. UW: أحدث 200 تنبيه تدفق في السوق          → قائمة أساسية
2. Finviz: أسهم فوليوم غير اعتيادي (40 صفاً)  → من فاتنا؟
3. لكل رمز فاتنا (15 كحد أقصى):
   UW /api/stock/{ticker}/flow-alerts        → تدفقه هو
4. الجميع يُسجَّل بنفس المعايير الأربعة
```

**Finviz يقرر من نفحص. UW يوفّر كل رقم يُحتسب.**

## الفلتر المستخدم
```
sh_avgvol_o500   متوسط فوليوم > 500 ألف
sh_relvol_o2     فوليوم نسبي > 2×
sh_price_o5      السعر > 5$
geo_usa          أسهم أمريكية
```
فضفاض عمداً — هذه شبكة لا مصفاة. نظام النقاط هو من يرفض.

## التكلفة على حصة UW
15 طلب إضافي لكل فحص × ~14 فحصاً يومياً = **~210 طلب/يوم**.
حصتك 30,000 يومياً — الهامش واسع.

## إن تعطّل Finviz
انتهاء التوكن أو انقطاع الخدمة **لا يوقف النظام**. `finviz.movers()`
يرجّع قائمة فارغة ويسجّل السبب، والفحص يكمل بـ UW وحده.

في السجل:
```
[finviz] got HTML, not CSV — FINVIZ_AUTH is wrong or expired
```
معناها التوكن انتهى. جدّده من رابط export في finviz.com.

# فحص ما قبل التشغيل

```bash
python check.py
```

يفحص كل ما يعتمد عليه النظام ويعطي حكماً واضحاً: المفاتيح الأربعة، القرص
الدائم وقابلية الكتابة عليه، أربع نقاط في UW، Finviz، وإرسال رسالة تيليجرام
فعلية. يخرج بكود غير صفري لو فشل شيء يمنع التشغيل.

`python check.py --no-telegram` لتخطي إرسال الرسالة.

شغّله بعد كل تغيير في المتغيرات، وقبل أول جلسة تعتمد عليها فعلاً.

## أخطر سطر فيه
```
[ FAIL ] 15m candles — 0 bars (...). Technical score is stuck at 0,
         so no total can reach 85 — NO ALERT WILL EVER FIRE
```

معناه أن باقة UW لا تعطيك شموع 15 دقيقة. النقاط التقنية (30) تبقى صفراً،
فأقصى مجموع 70 والعتبة 85 — **النظام لن يرسل تنبيهاً أبداً وسيبدو سليماً
تماماً في السجل**: يكتب `market closed` ثم `alive, waiting` ولا شيء غير ذلك.

هذا بعينه العطل الذي كان في النسخة الأولى (بسبب Finviz حينها)، ولذلك
`check.py` يصرخ به بهذه الصراحة بدل أن يبلّغ عن صفر محايد.

## لماذا ملف وليس أمراً تلصقه
طرفية Railway في المتصفح **لا تدعم لصق عدة أسطر** — تصلك رموز `^[[200~`
حرفيةً ويفشل الأمر بـ `command not found`. الملف يُشغَّل بسطر واحد قصير.
