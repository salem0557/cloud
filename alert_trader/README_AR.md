# بوت تنفيذ تنبيهات الخيارات (ورقي أولًا)

البوت لا يبحث عن فرص. يستقبل تنبيهات بوت المصدر من قناة تيليجرام، يستخرج بياناتها، يتحقق من العقد في أبيان ومن العرض/الطلب، يطبق حدودك، ثم ينفّذ (ورقيًا الآن) ويتابع الصفقة حتى الخروج ويكتب التقارير.

```
منشور القناة → تسجيل → استخراج → ربط/منع تكرار → تحقق (أبيان + أسعار) → حدود المخاطرة
→ منفّذ (ورقي | حقيقي) → متابعة الأوامر → إدارة المراكز → تقارير
```

المسار واحد للوضعين؛ الفرق فقط في `execution.py` (منفّذ ورقي أو حقيقي).

## 1) ما تم التحقق منه فعليًا (11 أكتوبر 2026)

| البند | النتيجة |
|---|---|
| قراءة حساب أبيان | ✓ عبر موصل أبيان في Claude: المحفظة الرئيسية، القوة الشرائية والمراكز والأوامر تُقرأ |
| سلسلة الخيارات في أبيان | ✓ تواريخ الانتهاء ورموز العقود (OCC) وأسعار التنفيذ والنوع |
| سعر العقد من أبيان | ⚠️ يعيد **FMV تقديريًا فقط** — لا عرض ولا طلب ولا أحجام ولا توقيت |
| المضاعف من أبيان | ⚠️ السلسلة لا تعيده؛ البوت يقبل فقط العقود القياسية (جذر OCC = الرمز) ويرفض المعدّلة |
| تفعيل الخيارات في حسابك | ✗ لا تكشفه الواجهة؛ تؤكده أنت من التطبيق (`abyan_options_enabled_confirmed`) |
| ربط البوت (برنامج على سيرفر) بأبيان | ✗ **غير متاح حاليًا كما هو موثّق** — انظر القسم 3 |
| عرض/طلب حقيقي | ✓ مصدر CBOE المجاني يعمل (مختبر) لكنه **متأخر 15 دقيقة** |
| استقبال القناة | ⏳ يحتاج اختبارًا بتوكن بوتك وقناتك (`probe`) — لم يُفترض |

## 2) استقبال القناة — لماذا الفحص إلزامي

أسئلة بوتات تيليجرام الشائعة تنص أن البوت لا يرى رسائل البوتات الأخرى «في المجموعات»، ولا توضح حالة منشور قناة نشره بوت آخر. لذلك يوفر المشروع طريقتين ويقارنهما على منشورات حقيقية:

* **`botapi`**: بوتك مشرف في القناة ويستقبل `channel_post` و`edited_channel_post`.
  الصلاحية المطلوبة: إضافة البوت **مشرفًا (Administrator)** في القناة؛ لا يحتاج صلاحية نشر أو حذف.
* **`userbot`**: حساب تيليجرام عادي (يفضَّل حساب مخصص) مشترك في القناة عبر Telethon. يرى كل ما يراه المشترك، بما فيها منشورات البوتات.
  المطلوب: `TG_API_ID` و`TG_API_HASH` من my.telegram.org، ثم `python -m alert_trader login` لإنشاء `TG_SESSION`.

الفحص:
```bash
python -m alert_trader probe --minutes 20      # أوقف البوت أثناء الفحص
```
يتحقق من التوكن، أن البوت مشرف، عدم وجود Webhook، ثم يستمع ويطبع كل منشور ومن نشره، وبالتوازي يقرأ الحساب آخر المنشورات. **الاستقبال يُعتبر مؤكدًا فقط إذا نشر بوت المصدر تنبيهًا أثناء الفحص ووصل.** ثم اضبط `CHANNEL_TRANSPORT` على الطريقة التي نجحت. أثناء التشغيل يعرض زر «🔌 فحص الربط» عدد المنشورات الواصلة عبر كل طريقة.

الأمان: يُقبل فقط `SOURCE_CHANNEL_ID`، واختياريًا `SOURCE_AUTHOR` (توقيع الناشر أو معرّف البوت الوسيط). نص المنشور يُعامل كبيانات فقط؛ لا يمكنه تغيير إعداد أو صلاحية أو تشغيل أمر.

## 3) أبيان — ما ينقص بالضبط

أبيان تنشر واجهة MCP مخصصة لـ«مساعد الذكاء الاصطناعي» للمستخدم. استخدمتها للقراءة من هذه الجلسة. لكن:

1. **الوصول من برنامج مستقل غير مؤكد.** صلاحية الموصل في Claude (OAuth) لا تُنقل إلى بوت على سيرفر. يلزم من أبيان: عنوان الواجهة (`ABYAN_MCP_URL`) وطريقة رسمية للحصول على توكن لبرنامجك (`ABYAN_MCP_TOKEN`) وتأكيد أن هذا الاستخدام مسموح.
2. **التنفيذ الآلي غير متاح بالوثائق الحالية:** الأوامر من هذه الواجهة «مسودات» يجب أن تؤكدها في تطبيق أبيان قبل إرسالها للسوق. أي تشغيل حقيقي بلا موافقة لكل صفقة يتطلب من أبيان واجهة تداول برمجية صريحة.
3. لا عرض/طلب ولا مضاعف ولا حالة تفعيل الخيارات في الواجهة.

المكتوب جاهز: `broker/abyan.py` عميل JSON-RPC (Streamable HTTP) بأسماء الأدوات والحقول التي تحققت منها، وفي الوضع الورقي **يرفض أدوات الكتابة قبل أن يخرج أي طلب**. إن لم يتوفر `ABYAN_MCP_URL` يرفض البوت التنبيهات بسبب «لا يوجد اتصال بأبيان» — إلا إذا فعّلت `paper_allow_without_broker_verification` فتُوسم كل صفقة «لم يُتحقق من أبيان» ولا تُحسب اختبارًا لأبيان.

لا يفتح البوت حسابات ولا ينقل أموالًا ولا يملك أدوات سحب أو تحويل.

## 4) مصدر العرض/الطلب للمحاكاة

| `QUOTE_PROVIDER` | الوصف |
|---|---|
| `cboe` (افتراضي) | مجاني بلا مفتاح، **متأخر 15 دقيقة**. مع `allow_delayed_quotes=false` (الافتراضي) سيرفض كل التنبيهات بسبب «أسعار متأخرة» — وهذا مقصود. |
| `polygon` + `POLYGON_API_KEY` | لحظي إن كانت خطتك تشمل اقتباسات الخيارات؛ كل سعر يُوسم «متأخر» أو لا حسب الخطة. |
| `tradier` + `TRADIER_TOKEN` | لحظي لحسابات Tradier الممولة؛ `TRADIER_DELAYED=1` للـ sandbox. |

لتجربة المسار بالمصدر المجاني: `allow_delayed_quotes=true` و`max_quote_age_sec` ≥ 960 — وستظهر كل الأسعار في التقارير «متأخرة» ولن تُعتبر محاكاة دقيقة. FMV من أبيان يُستخدم للمقارنة فقط ولا يُعتمد سعرًا للتنفيذ؛ آخر سعر تداول لا يُستخدم للتنفيذ إطلاقًا.

## 5) قواعد المحاكاة الورقية

* شراء عند الطلب + انزلاق (`slippage_ticks`)، بيع عند العرض − انزلاق، ولا يتجاوز سعر الحد أبدًا.
* لا تنفيذ بلا سعر حديث، أو بسعر توقيته قبل وصول الأمر (`simulated_latency_sec`)، أو بلا حجم معروض.
* كل سعر جديد ينفّذ حتى حجمه المعروض فقط، ولا يُستهلك نفس السعر مرتين ← تنفيذ جزئي واقعي.
* الرسوم: جدول أبيان المنشور (لكل أمر مع حد أدنى) + ضريبة 15% على العمولة + رسوم أطراف أخرى قابلة للضبط. العمولة تُحتسب مرة للأمر حتى لو نُفذ على دفعات.
* حجز النقد عند إرسال أمر الشراء وتحريره عند التنفيذ/الإلغاء/الانتهاء؛ دفتر (`ledger`) لكل حركة.
* المحفظة الورقية منفصلة تمامًا؛ قراءة حسابك الحقيقي تظهر منفصلة ولا تختلط.

## 6) إدارة الصفقة

* **ربط التحديث/الخروج:** بالرد على رسالة الدخول ← معرّف التنبيه ← رمز العقد ← الأصل والنوع. أكثر من صفقة مطابقة = رفض مع السبب.
* **التكرار:** مفتاح الصفقة (القناة:الرسالة) فريد في قاعدة البيانات؛ إعادة الإرسال أو التعديل أو إعادة التشغيل لا تشتري مرتين. نفس المعرّف أو نفس العقد خلال `duplicate_window_sec` = مكرر.
* **التعديل:** تعديل رسالة دخول نُفذت يُطبق كتحديث للوقف/الأهداف فقط؛ تغيير العقد يُرفض وينبهك. تعديل تنبيه مرفوض يُعاد تدقيقه بعمر الرسالة الأصلي.
* **تعدد الأهداف:** `targets_split` (مثلًا 50%/50%): عند كل هدف يُباع جزؤه بالأرضية، والهدف الأخير يغلق الباقي. عقد واحد يُباع كاملًا عند الهدف الأول. خيار نقل الوقف لسعر الدخول بعد الهدف الأول.
* **الوقف:** عندما يصل العرض للوقف يُرسل أمر بيع محدد عند العرض − انزلاق. **الوقف ليس سعر خروج مضمونًا.**
* **بلا خروج من المصدر:** `exit_without_source` (وقف/هدف نسبي، مدة احتفاظ قصوى، إغلاق نهاية الجلسة).
* **الانتهاء:** إغلاق إلزامي قبل الإغلاق بـ `close_before_expiry_minutes` يوم الانتهاء. إن بقي مركز بعد الإغلاق يُسوّى ورقيًا بالقيمة الذاتية مع تنبيه أن OCC يمرّن تلقائيًا العقد داخل المال ≥ 0.01$.
* **الأوامر:** محددة السعر دائمًا، بصلاحية (`entry_order_ttl_sec`/`exit_order_ttl_sec`). الحالات: مسجل ← مرسل ← مقبول ← جزئي ← مكتمل/ملغى/مرفوض/منتهٍ/**غير معروف**. «غير معروف» (انقطاع بعد الإرسال) يُطابق لدى الوسيط قبل أي إعادة إرسال.
* **الأعطال:** تعطل الأسعار أو أبيان أو تجاوز حد الخسارة اليومية ← إيقاف الدخول الجديد تلقائيًا، مع استمرار متابعة المراكز والخروج عند عودة البيانات.
* **التقويم:** عطل NYSE والإغلاق المبكر (13:00) والتوقيت الصيفي تلقائيًا؛ كل الأوقات تُعرض بتوقيت نيويورك والرياض.

حد الخسارة اليومية (`daily_loss_method`): `realized` = صافي المحقق اليوم بتوقيت نيويورك بعد كل الرسوم؛ `realized_plus_unrealized` = المحقق + غير المحقق للمراكز المفتوحة مُقيّمة بسعر العرض.

## 7) واجهة تيليجرام (لمعرّفك فقط)

أزرار: 📊 الحالة · 💼 المحفظة · 📈 المراكز · 🧾 الأداء · ✅ المقبولة · ❌ المرفوضة · ⚙️ الإعدادات · ⏸ إيقاف الدخول · ▶️ استئناف الدخول · 🛑 إغلاق جميع المراكز (بتأكيد، ولا يوقف الدخول) · 📅 تقرير اليوم · 🗓 تقرير الأسبوع · 🔌 فحص الربط.

الإشعارات: قبول/رفض مع السبب، **أُرسل أمر** (ليس تنفيذًا)، تنفيذ جزئي، تنفيذ كامل، خروج، أعطال — مع منع تكرار الأعطال لمدة 15 دقيقة. كل رسالة تبدأ بـ «🧪 [ورقي]».

التقرير اليومي يُرسل 16:20 نيويورك في أيام التداول؛ تقرير الأسبوع تلقائيًا بعد 7 أيام من بدء المحاكاة (الموعد يُسجل عند أول تشغيل ويظهر في الحالة مع عدد الجلسات).

## 8) الإعداد والتشغيل

```bash
pip install -r requirements.txt
cp alert_trader/trading_settings.example.json data/trading_settings.json   # ثم ضع قيمك
python -m alert_trader check          # فحص الإعداد والاتصال (لا يطبع أي سر)
python -m alert_trader probe --minutes 20
python -m alert_trader run
```

متغيرات البيئة (أدخلها بنفسك، لا ترسلها في المحادثة) — انظر قسم «alert_trader» في `.env.example`.

**Railway:** خدمة جديدة من نفس المستودع، أمر التشغيل `python -m alert_trader run`، وأرفق Volume (مثلًا `/data`)؛ البوت يكتشفه عبر `RAILWAY_VOLUME_MOUNT_PATH` ويضع فيه `alert_trader.db` و`trading_settings.json`. نسخة واحدة فقط من الخدمة (تشغيل نسختين بنفس التوكن يسبب تعارض 409).

**الاستعادة بعد الانقطاع:** أعد التشغيل فقط. عند البدء: الأوامر التي لم تُرسل تُلغى، الأوامر المفتوحة تُستأنف متابعتها، و(في الحقيقي) الأوامر غير المعروفة تُطابق مع الوسيط والمراكز تُقارن؛ أي اختلاف يوقف الدخول وينبهك. منشورات القناة أثناء التوقف: Bot API يحتفظ بالتحديثات 24 ساعة فتصل عند العودة لكنها تُرفض إن تجاوزت `max_alert_age_sec`؛ لا شراء متأخر.

نسخ احتياطي: انسخ `alert_trader.db` (SQLite بوضع WAL) أثناء توقف البوت أو بـ `sqlite3 alert_trader.db ".backup b.db"`.

## 9) الانتقال للحقيقي (لاحقًا، يدويًا فقط)

لا ينتقل البوت تلقائيًا عند انتهاء الأسبوع. التفعيل يتطلب **كلها معًا**:
`"mode": "live"` و`"demo": false` وكل القيم المطلوبة (منها `live_capital_usd` و`abyan_options_enabled_confirmed: true`) + `LIVE_TRADING_ARMED=1` + اتصال أبيان قابل للكتابة + إعادة تشغيل. المنفّذ الحقيقي يعيد التحقق من ملف الإعدادات ومتغير البيئة قبل **كل** أمر. ومع ذلك يبقى مانع أبيان (القسم 3) قائمًا حتى توفر أبيان واجهة تداول برمجية.
