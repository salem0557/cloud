# محلل التشارت — وكيل تلقرام (analyst_agent)

وكيل يعيش في قروب تلقرام كحساب مستخدم (userbot). ترسل له صورة تشارت مع طلبك،
فيتعرّف على الرمز والفريم، يجيب البيانات الحقيقية بنفسه، يرسم تشارت جديد
بالمؤشرات المهمة، ويرد بقراءة فنية حاسمة فيها خطة دخول وستوب وأهداف.

---

## كيف يفكر الوكيل (المهم تفهمه)

الصورة تُستخدم **للتعرّف فقط**: أي رمز؟ أي فريم؟ وش رسمت عليها؟
الأسعار والمستويات **لا تُقرأ من الصورة** أبداً — تُحسب من بيانات حقيقية تُنزَّل
من السوق. السبب بسيط: البكسل ما له رقم خلفه، ولو قرأنا الدعم من الصورة لصار
التحليل تخميناً.

ثم تُحسب كل الأرقام (المتوسطات، RSI، MACD، ADX، ATR، بولنجر، الفوليوم، الدعوم
والمقاومات، فيبوناتشي، VWAP، نماذج الشموع، الدايفرجنس) ويُبنى **الحكم** عليها
بمحرّك حسابي ثابت: اتجاه + درجة ثقة + دخول + ستوب + أهداف + العائد/المخاطرة.
أخيراً يكتب موديل Groq القراءة العربية **حول هذا الحكم**، وممنوع عليه تغيير أي
رقم أو اختراع رقم غير موجود في البيانات.

يعني: الثقة في الرد ليست كلاماً — هي ناتج حساب، ونفس التشارت يعطي نفس الحكم دائماً.

## الفريم هو الأساس

الترتيب في تحديد الفريم:

1. **ما تكتبه في الرسالة** (أقوى إشارة): «15 دقيقة»، «4 ساعات»، «يومي»، `M15`، `H4`، `240`، `1D`.
2. **ما هو ظاهر في الصورة** إن لم تكتب شيئاً.
3. الافتراضي (`ANALYST_DEFAULT_FRAME`، وهو اليومي).

الفريمات المدعومة: `1m 2m 3m 5m 10m 15m 30m 45m 1h 2h 3h 4h يومي أسبوعي شهري`
(الفريمات التي لا يوفرها المصدر أصلاً مثل 4 ساعات تُبنى بإعادة تجميع الساعة).
ومع كل فريم يُقرأ **الفريم الأعلى** للسياق، فإن كان معاكساً يُنقص الوكيل درجة
الثقة ويقول لك صراحة: الصفقة عكس الاتجاه الأكبر.

## الرموز التي يفهمها

| تكتب | يفهم |
|---|---|
| `TSLA` أو `$TSLA` أو «تسلا» | TSLA |
| «أرامكو» أو `2222` | 2222.SR |
| «سابك»، «الراجحي»، «معادن»، `stc`… | رمز تداول الصحيح |
| «تاسي» | ^TASI.SR |
| `BTC`، «بيتكوين»، `BTCUSDT` | BTC-USD |
| «الذهب»، `XAUUSD` | GC=F |
| `EURUSD` | EURUSD=X |
| «ناسداك»، `SPX` | ^IXIC، ^GSPC |

لو الرمز غير واضح، يسألك بدل أن يخمّن. ولو جاء الرمز من الصورة والنص معاً،
**النص يفوز**.

## التشغيل

### 1) مفتاح Groq
من [console.groq.com/keys](https://console.groq.com/keys) — مجاني.
لا تحتاج تحديد الموديل: الوكيل يسأل Groq عن الموديلات المتاحة ويختار الأفضل،
فإن تعطّل موديل انتقل للذي بعده تلقائياً.

### 2) حساب اليوزر بوت
من [my.telegram.org](https://my.telegram.org) → API development tools → خذ
`api_id` و `api_hash`، وضعهما في `.env`، ثم سجّل الدخول مرة واحدة:

```bash
python -m analyst_agent.login
```

يطلب رقم الجوال والكود، ويطبع سطر `TELEGRAM_SESSION=...` — انسخه إلى `.env`.
هذا السطر يساوي دخولاً كاملاً للحساب: لا تشاركه ولا ترفعه للمستودع.

> الأفضل استخدام حساب تلقرام منفصل للوكيل، لا حسابك الأساسي.

### 3) `.env`

```env
GROQ_API_KEY=gsk_xxx
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=xxxxxxxx
TELEGRAM_SESSION=1BQANOTEuMTA4...
ANALYST_OWNER_IDS=<معرّفك في تلقرام>
```

### 4) التشغيل

```bash
pip install -r requirements.txt
python -m analyst_agent.userbot
```

ثم أضف حساب الوكيل إلى القروب، وجرّب:

```
حلل TSLA فريم 15 دقيقة        (مع صورة أو بدونها)
أرامكو يومي
BTC 4 ساعات
```

أو أرسل صورة تشارت واكتب معها «حلل 15 دقيقة»، أو **رد** على صورة قديمة بكلمة «حلل».

### قبل تلقرام: جرّبه من الطرفية

```bash
python -m analyst_agent.cli TSLA 15m --out chart.png
python -m analyst_agent.cli --image shot.png "حلل 4 ساعات" --json
python -m analyst_agent.cli 2222.SR 1d --no-news
```

### النشر على Railway
`Procfile` فيه صفّان: `worker` للماسح القديم و `analyst` لهذا الوكيل.
أنشئ خدمة ثانية على نفس المستودع واجعل أمر التشغيل:
`python -m analyst_agent.userbot`، وضع متغيرات البيئة أعلاه فيها.

## متى يتكلم ومتى يسكت

| المكان | الشرط |
|---|---|
| قروب | كلمة تنبيه («حلل»، «تحليل»، «شارت»…) أو منشن أو رد على رسالة الوكيل |
| قروب | صورة بلا نص: يسكت، إلا إذا فعّلت `ANALYST_ANSWER_BARE_PHOTOS=true` |
| خاص | يحلل أي تشارت مباشرة |
| رسائلك أنت (نفس حساب الوكيل) | يسكت إلا إذا كتبت كلمة تنبيه |

وفيه فترة انتظار `ANALYST_USER_COOLDOWN` لكل مستخدم (لا تنطبق على `ANALYST_OWNER_IDS`)،
وحدّ للطلبات المتزامنة `ANALYST_MAX_CONCURRENT`.

## ما داخل الرد

* **التشارت**: شموع الفريم المطلوب + EMA 20/50/200 + بولنجر + الدعوم والمقاومات
  بعدد لمساتها + منطقة فيبوناتشي الذهبية + VWAP (للفريمات اللحظية) + خطوط الدخول
  والستوب والأهداف + لوحة أرقام + فوليوم + RSI + MACD.
  كتابة التشارت بالإنجليزية لأن matplotlib لا يصل الحروف العربية؛ التحليل نفسه عربي.
* **النص**: الخلاصة ودرجة الثقة، القراءة الفنية بالأدلة الرقمية، المستويات،
  الخطة (دخول/ستوب/أهداف/العائد للمخاطرة/نسبة التعادل)، ما يلغي السيناريو،
  ثم الأخبار ومزاج المتداولين.

## قاعدة الستوب (مقصودة)

الستوب أداة حماية لا زينة: يُحسب من أقرب دعم/مقاومة حقيقي أو من ATR — أيّهما
أضيق — مع حدّ أدنى حتى لا يُضرب بضجيج السعر، وحدّ أعلى حتى لا يتحوّل لخسارة كبيرة.
وإن كان العائد/المخاطرة أقل من 1 يقولها لك صراحة ويقترح انتظار سعر أفضل.

## بنية الملفات

| الملف | الدور |
|---|---|
| `frames.py` | فهم الفريم من العربي/الإنجليزي/`M15`/`240` |
| `symbols.py` | تحويل أي اسم أو رقم إلى رمز صحيح |
| `market.py` | تنزيل الشموع للفريم المطلوب + الفريم الأعلى |
| `indicators.py` | كل الأرقام: مؤشرات، مستويات، نماذج، دايفرجنس |
| `verdict.py` | القرار: اتجاه، ثقة، دخول، ستوب، أهداف |
| `chart.py` | رسم التشارت المشروح |
| `vision.py` | قراءة الرمز والفريم من الصورة (Groq vision) |
| `news.py` | العناوين + StockTwits + موعد النتائج |
| `prompts.py` | شخصية المحلل + قالب بديل يعمل بدون إنترنت AI |
| `analyst.py` | يربط الكل: رسالة → تشارت + تحليل |
| `userbot.py` | تلقرام (Telethon) |
| `cli.py` | تشغيل من الطرفية للتجربة |

## حدود يجب أن تعرفها

* البيانات من Yahoo: مؤجّلة قليلاً للسوق السعودي، وبيانات الدقيقة الواحدة لا
  تتوفر لكل رمز — عند عدم توفرها يرفع الوكيل الفريم ويخبرك بذلك في الرد.
* لا يقرأ الأسعار من الصورة (بالتصميم)، فإن كانت صورتك لرمز لا يعرفه المصدر
  فلن يحلله.
* هذا تحليل فني آلي، وليس توصية استثمارية.
